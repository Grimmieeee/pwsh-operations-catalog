# FIELD // KIT — approved design baseline

Locked by the owner on October 17, 2026. Future visual changes require an in-chat preview and explicit approval before publication. Routine bug fixes may restore this baseline; do not redesign while working on scripts.

## Identity

- Home Screen name: `F I E L D //  K I T`; dark icon with mint `//`.
- Main wordmark: existing Raleway treatment; a visible gap after FIELD and a larger gap before KIT.
- Low sidebar footer: BY above BURNSID//. BURN is bright; SID// muted, with tight slashes after D.
- BY sits .43em lower than its normal position, with its visible B edge aligned to the larger B. The larger wordmark is 8% larger than the size that makes its B span BY.
- EST. 2026 sits at the far right on the wordmark baseline. EST. is bright, 2026 muted; its type size matches BY.
- Preserve proportions across sidebar widths. Scale only as needed to fit; do not wrap the date below the name.
- Retain the low placement and one device safe-area inset, not two.

## Catalog and cards

- Minimal list: task name, exact-version operator-verification mark when earned, and access flags. No row versions or platform badges.
- Parenthetical search count; small verification key at upper right. No redundant controls below search.
- Card order: USE FOR, INPUT, CHECKS, GUARDS, connection commands, useful Details, source actions. Omit empty sections.
- INPUT distinguishes what the technician brings from script-provided choices. CHECKS and GUARDS describe the exact script, not generic assurances.
- Compact REQUIRES supports hover, tap and keyboard. Long connection commands expand; COPY always copies the full command.
- Preserve muted flag borders and readable destructive red. No extra verification borders or decorative badges.
- Versions stay inside cards. No new VERIFIED marks without exact-version operator evidence.

## Acceptance

Preview visual changes in chat before publishing. Run site and required security checks, inspect live behavior and retain screenshot evidence. A site UI pass does not prove PowerShell runtime behavior.
